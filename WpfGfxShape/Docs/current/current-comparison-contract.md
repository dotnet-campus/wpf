# 当前权威规则：严格双进程对照

本页集中记录用户最新澄清，覆盖历史文档中冲突的规则、预算和授权表述。恢复入口见 [current-recovery.md](current-recovery.md)。

## 对照合同

1. 允许且要求官方原版参与独立对照。禁止的是“只给原版写测试，没有候选相同测试与比较”，不是禁止原版参与。
2. 两个独立业务进程分别只加载官方 gfx 或候选 gfx；禁止同进程双版本。监督/比较进程不得靠双加载实现比较。
3. 两侧使用同一冻结 harness、相同上层逻辑、固定 runtime、输入、配置和调用顺序；唯一业务实现差异是 gfx DLL。角色、输出目录及模块身份收据只能用于选择实现和记录证据，不得改变业务行为。
4. 严格比较完整像素、事件、元数据、错误和生命周期可观察契约；两个采样点、无异常、加载成功或候选自身重复一致均不等于完整对照。
5. 禁止候选委托原版、fallback、候选专属补偿，以及修改 expected、容差或其他标准追绿。官方基线也必须受同样用例和合同约束。
6. 验收问题修验收，真实兼容问题修生产；不得加入生产测试耦合或以验收钩子掩盖兼容问题。
7. 记录两侧真实进程退出、模块路径/身份、原始输出及清理证据。缺失证据明确 Unknown/NotRun；失败、超时、未进入业务和负控拒绝不得抹成通过。
8. 桌面/system/native control 前置失败必须记录最早失败阶段；尚未进入的官方/候选业务为 NotRun/NotReached。没有因果证据不得归为环境失败、产品失败或严格等价通过。
9. role 分支仅允许目录、实现身份选择及取证差异；不得改变业务调用、输入、配置、事件等待/释放顺序或增加候选专属补偿。历史 role 路由修正的有限通过不是此类业务差异的授权。

## 执行与分工

- 本串行任务1只探索和修改文档：生产/验收源码修改0，build/test/publish/Windows沙盒执行0；不要求再次确认原版对照权限。
- 专用 build/test/publish/Windows 沙盒授权继续有效，供后续代码任务按分派使用。本任务的执行0不是后续禁止执行。
- 禁止命令行终端和任何脚本；后续仅使用获准专用工具。旧阶段“预算耗尽”“另需授权”“原版永禁”不得冒充本轮限制，不编造新的次数上限。
- 串行一次一个子智能体；本任务不继续派生代码或运行任务。

## 历史解释

历史“原版永禁”是已被用户纠正的误导；生产实现不得依赖原版/fallback 的禁令仍有效。旧绿只证明各自报告明确覆盖的有限门，不能作为完全等价认证。历史账目、真实失败与未决项保留，参见 [历史索引](history/README.md)。
